# 湿度探头 Modbus ID 配置记录

## 配置结果

- 接口：RS485，Modbus RTU
- 串口设备：`/dev/ttyUSB1`
- 串口转换器：USB2.0-Serial（USB ID：`1a86`）
- 通信参数：`9600 bps`、8 数据位、无校验、1 停止位（8N1）
- 原设备 ID：`1`
- 新设备 ID：`3`
- ID 配置寄存器：`0x0100`
- 波特率配置寄存器：`0x0101`
- 设备当前波特率代码：`4`（对应本设备的 9600 bps）

## 接线与通信确认

探头通过 USB-RS485 转换器连接电脑。探测到的 Linux 串口为：

```text
/dev/ttyUSB1
```

在 `9600, 8N1` 下扫描 Modbus 地址 `1～247`，只有 ID `1` 返回有效响应。

读取保持寄存器 `0x0000` 起始的两个寄存器：

```text
发送：01 03 00 00 00 02 C4 0B
接收：01 03 04 02 8D 00 FA EB E3
```

数据解析：

- `0x028D = 653`，湿度约为 `65.3 %RH`
- `0x00FA = 250`，温度约为 `25.0 ℃`
- 两个测量值的缩放系数均为 `0.1`

因此本设备的主要测量寄存器为：

| 寄存器 | 内容 | 数据换算 |
| --- | --- | --- |
| `0x0000` | 相对湿度 | 原始值 ÷ 10，单位 `%RH` |
| `0x0001` | 温度 | 有符号原始值 ÷ 10，单位 `℃` |

## 配置寄存器确认过程

首先尝试了许多同类传感器使用的地址寄存器 `0x07D0`：

```text
01 06 07 D0 00 03 C9 46
```

设备虽然原样回显该帧，但重启后仍响应 ID `1`，ID `3` 无响应，说明 `0x07D0` 不是该探头实际使用的配置寄存器。需要注意：写单寄存器命令被原样回显，只能说明报文被设备接收，不能单独证明配置已经生效。

继续只读检查常见参数区后，得到：

```text
读取 0x0100～0x0101
返回值：0001 0004
```

其中：

- `0x0100 = 1`，与当前设备 ID 一致
- `0x0101 = 4`，与当前 9600 bps 通信参数对应

由此确认本探头使用 `0x0100` 配置设备 ID。

## 将 ID 从 1 修改为 3

使用 Modbus 功能码 `0x06`（写单个保持寄存器），向寄存器 `0x0100` 写入 `0x0003`：

```text
发送：01 06 01 00 00 03 C8 37
接收：01 06 01 00 00 03 C8 37
```

字段说明：

| 字节 | 含义 |
| --- | --- |
| `01` | 修改前的设备 ID |
| `06` | 写单个保持寄存器 |
| `01 00` | ID 配置寄存器 `0x0100` |
| `00 03` | 新 ID `3` |
| `C8 37` | Modbus CRC16，低字节在前 |

## 修改结果验证

修改后使用新 ID `3` 读取温湿度：

```text
发送：03 03 00 00 00 02 C5 E9
接收：03 03 04 02 86 00 FD F8 23
```

解析结果：

- 湿度：`0x0286 = 646`，即 `64.6 %RH`
- 温度：`0x00FD = 253`，即 `25.3 ℃`

同时再次查询旧 ID `1`，设备不再响应。因此确认设备 ID 已成功由 `1` 修改为 `3`。

## 后续使用

使用新 ID `3` 读取温湿度的固定请求帧为：

```text
03 03 00 00 00 02 C5 E9
```

响应中的数据位置：

```text
03 03 04 HH HH TT TT CRC_L CRC_H
```

- `HH HH`：湿度原始值，除以 10 得到 `%RH`
- `TT TT`：有符号温度原始值，除以 10 得到 `℃`

## 注意事项

1. 修改 ID 时，RS485 总线上最好只连接一个待配置探头，避免相同 ID 的设备同时应答。
2. 新 ID 应保持唯一，建议使用 `1～247` 范围。
3. 本探头的 ID 寄存器是 `0x0100`，不能照搬其他探头常见的 `0x07D0`。
4. 写入后必须分别测试新、旧 ID；仅凭功能码 `0x06` 的回显不能判断最终配置是否成功。
5. 若无法通信，依次检查探头供电、A/B 极性、共地、波特率、校验方式和设备 ID。
