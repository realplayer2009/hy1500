# PA0715-N 批量安装指南

适用已准备好的同款 PA0715-N / RK3562 / Android 13 屏。安装电脑只需 ADB；屏内不需要 Termux、X11 或编译工具。解压安装包后，在解压目录打开 PowerShell。

若屏采用 `zysj` 厂商服务、工程设置包为 `com.sz.zysj.settings`，使用 [ZYSJ 固件安装与恢复](DEVICE_PANEL_ZYSJ.md)：这套固件的自启、守护和静态 Logo 路径与下文不同。

正常流程：连接屏 → 安装应用并设置自启 → 首次安装开机画面 → 重启。无需登记序列号、逐项检查系统属性或计算校验值；无需接子板。已有品牌开机画面的屏，更新时只做第 1、2、4 步。

## 1. 连接屏

安装电脑与屏接在同一网络，厂商设置中开启“网络 ADB 调试”。设备地址由现场网络动态分配，不要沿用本文或旧记录中的 IP。优先读取屏上显示的 `IP:端口`；地址未知时，从安装电脑实际连接的网口确定网段，并扫描开放 TCP 5555 的主机（Linux 可用 `nmap -n -p 5555 --open <屏所在网段/CIDR>`）。对候选地址执行 `adb connect`，再用 `adb -s <IP:端口> shell getprop ro.product.model` 确认为 `rk3562_t` 后再安装。

```powershell
$d = Read-Host '输入现场发现的屏 IP:端口'
adb connect $d
adb -s $d shell getprop ro.product.model
```

## 2. 安装应用并设置自启

```powershell
powershell -ExecutionPolicy Bypass -File .\android\provision_apk.ps1 -DeviceAddr $d -Kiosk
if ($LASTEXITCODE -ne 0) { throw '安装失败，先处理报错' }
```

脚本覆盖安装 APK、设置设备所有者、默认 HOME，并通过屏厂商工程设置配置开机自启和守护包名，然后启动控制界面。进入应用后锁定 Android 系统导航，屏内左侧页面导航照常使用。更新会保留原配置和历史数据；不要卸载或清除应用数据。新屏首次启动使用包内默认参数，实际使用前通过界面按接线与工况设置。

## 3. 首次安装开机画面

只用于本批同款、同固件屏（`rk3562_t-userdebug 13 TQ3C.230805.001.B2 eng.server.20260421.150515 release-keys`）。其他固件的厂商 Logo 接口可能不同。

### 3.1 获取 root，启用系统写入

```powershell
adb -s $d root
Start-Sleep -Seconds 2
adb connect $d
adb -s $d remount
```

如果出现 `Now reboot your device for settings to take effect` 或其他要求重启的提示，即使同时显示 `remount succeeded`，也先执行：

```powershell
adb -s $d reboot
# 等屏重新启动后继续；若 IP 改变，重新扫描并更新 $d
adb connect $d
adb -s $d root
Start-Sleep -Seconds 2
adb connect $d
adb -s $d remount
```

本次新屏首次 remount 就走了这个分支。系统分区通过 overlayfs 开放写入，重启才能激活第一次创建的覆盖层。

### 3.2 静态 Logo

先在屏内保留一次原厂备份，重复执行不会覆盖。再上传并写入品牌 Logo：

```powershell
adb -s $d shell 'set -e; if [ ! -e /data/local/tmp/rs485-logo.factory.img ]; then dd if=/dev/block/by-name/logo of=/data/local/tmp/rs485-logo.factory.img.new bs=1M; mv /data/local/tmp/rs485-logo.factory.img.new /data/local/tmp/rs485-logo.factory.img; fi'
if ($LASTEXITCODE -ne 0) { throw 'Logo 备份失败，停止' }
adb -s $d push .\assets\boot_logo.bmp /data/local/tmp/rs485-boot-logo.bmp
if ($LASTEXITCODE -ne 0) { throw 'Logo 上传失败，停止' }
adb -s $d shell service call xzjh 117 s16 /data/local/tmp/rs485-boot-logo.bmp s16 /data/local/tmp/rs485-boot-logo.bmp
adb -s $d shell sync
```

### 3.3 宣传动画

```powershell
adb -s $d shell 'set -e; if [ ! -e /system/media/bootanimation.zip.orig.bak ]; then cp -p /system/media/bootanimation.zip /system/media/bootanimation.zip.orig.bak; fi'
if ($LASTEXITCODE -ne 0) { throw '动画备份失败，停止' }
adb -s $d push .\android\dist\bootanimation.zip /data/local/tmp/rs485-bootanimation.zip
if ($LASTEXITCODE -ne 0) { throw '动画上传失败，停止' }
adb -s $d shell 'set -e; cp /data/local/tmp/rs485-bootanimation.zip /system/media/bootanimation.zip.new; chown root:root /system/media/bootanimation.zip.new; chmod 644 /system/media/bootanimation.zip.new; chcon u:object_r:system_file:s0 /system/media/bootanimation.zip.new; mv /system/media/bootanimation.zip.new /system/media/bootanimation.zip; sync'
if ($LASTEXITCODE -ne 0) { throw '动画替换失败，停止' }
```

本固件只读取上述系统路径，放到 `/data/local/bootanimation.zip` 不生效。无需重新转换视频。

## 4. 重启完成

```powershell
adb -s $d reboot
```

等屏自行进入控制界面，开机顺序应为品牌静态 Logo → 宣传视频 → 控制界面。无需手动启动应用。未接子板时显示“正在搜索子板”、无数据记录属于预期状态，安装不要求做负载、接线或高压联锁测试。

## 5. 后续多台更新

新建 `devices.txt`，一行一个 `IP:端口`。更新只覆盖 APK，不重复写开机画面：

```powershell
$devices = Get-Content .\devices.txt | Where-Object { $_.Trim() } | ForEach-Object { $_.Trim() }
foreach ($d in $devices) {
    powershell -ExecutionPolicy Bypass -File .\android\provision_apk.ps1 -DeviceAddr $d -Kiosk
    if ($LASTEXITCODE -ne 0) { throw "更新失败：$d" }
    adb -s $d reboot
}
```

使用本次重新编译后交付的安装包；源码更新后须重新运行 `bash android/build_apk.sh` 并重新打包交付 ZIP，旧 ZIP 不会自动跟随源码或 APK 更新。安装电脑无需编译。

## 6. Linux 安装

在项目根目录或安装包解压目录执行。首次安装开机画面时，第 3 节 `adb` 命令相同：将 `$d` 写成 `"$d"`、本机路径的 `\` 改成 `/`，`Start-Sleep -Seconds 2` 改成 `sleep 2`。遇到命令报错应停止处理，不继续覆盖。

```bash
# 先用 ip -br -4 addr 和 ip route 确认连接屏的网口及其网段；
# 地址未知时扫描该网段：nmap -n -p 5555 --open <屏所在网段/CIDR>
read -r -p '输入现场发现的屏 IP:端口: ' d
adb connect "$d"
adb -s "$d" shell getprop ro.product.model
adb -s "$d" install --no-streaming -r android/dist/RS485Control-arm64-v8a-debug.apk
# 首次启用导航锁执行一次；后续 APK 更新不重复设置设备所有者
adb -s "$d" shell dpm set-device-owner --user 0 com.rs485.control/.KioskAdminReceiver
# 确保覆盖安装后设备所有者组件仍为活动管理员
adb -s "$d" shell dpm set-active-admin --user 0 com.rs485.control/.KioskAdminReceiver
adb -s "$d" shell cmd package set-home-activity --user 0 com.rs485.control/.MainActivity
# 通过 PA0715-N 厂商工程设置配置开机自启与守护
adb -s "$d" shell settings put system xzjh_auto_boot_package_name com.rs485.control
adb -s "$d" shell settings put system xzjh_daemon_package_name com.rs485.control
adb -s "$d" shell am start -W -n com.rs485.control/.MainActivity
# 新屏在这里完成第 3 节开机画面安装，之后重启
adb -s "$d" reboot
```

## 7. 出问题时再查

| 现象 | 原因及处理 |
|---|---|
| 找不到 adb | 将 Android SDK Platform-tools 加入 PATH，重新打开终端 |
| `No route to host` / offline | 屏还没启动完、IP 已变化，或电脑和屏不在同一网段；到屏设置查看当前地址，或按第 1 节从实际连接网口扫描 TCP 5555，再 `adb disconnect <旧地址>`、`adb connect <当前地址>`。Linux 可用 `ip neigh` 查看已发现的邻居；网口亮只代表物理连接 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 新旧 APK 签名不同，换回同签名构建；不要卸载以免丢参数和历史。构建机应保管当前 debug 签名密钥 |
| 启动时报 `libc++_shared.so has bad ELF magic` | 设备上的 native 库解包内容损坏。用 `adb -s <地址> install --no-streaming -r android/dist/RS485Control-arm64-v8a-debug.apk` 覆盖安装并重新启动应用；`-r` 保留现场数据 |
| 启动时报 `KioskAdminReceiver does not exist or is not owned by uid` | 系统记录的设备所有者未列为活动管理员。运行 `adb -s <地址> shell dpm set-active-admin --user 0 com.rs485.control/.KioskAdminReceiver`，再启动应用；不要移除设备所有者或清除应用数据 |
| `Permission denied` | reboot 后 root 状态丢失；重新 `adb -s <地址> root`，稍后重连 |
| 动画路径只读 | 按第 3.1 节 root、remount；首次要求 reboot 时先重启，再 root、remount |
| 重启进入原厂桌面 | 重做第 2 节默认 HOME 和两项厂商自启设置 |
| `set-device-owner` 失败 | 已有其他设备所有者或系统账户可能阻止设置；按报错处理，勿清除应用数据或恢复出厂。仅设置 HOME 不能禁用系统导航 |
| 屏上还是旧界面 | 从当前源码重新编译 APK，并替换交付 ZIP 内的 APK；`install -r` 保留旧参数是正常行为，不表示代码没更新 |

维护时先通过 ADB 解锁，再打开系统设置；维护完成后用下面的恢复命令重新锁定：

```powershell
adb -s $d shell am broadcast -a com.rs485.control.MAINTENANCE -n com.rs485.control/.KioskMaintenanceReceiver --ez enabled true
adb -s $d shell am start -a android.settings.SETTINGS
# 维护完成，恢复导航锁并回到控制界面
adb -s $d shell am broadcast -a com.rs485.control.MAINTENANCE -n com.rs485.control/.KioskMaintenanceReceiver --ez enabled false
adb -s $d shell am start -W -n com.rs485.control/.MainActivity
```

需要恢复原厂画面时，先按第 3.1 节获取 root 和系统写入权限，再按需执行：

```powershell
# 恢复动画
adb -s $d shell 'set -e; cp /system/media/bootanimation.zip.orig.bak /system/media/bootanimation.zip; chown root:root /system/media/bootanimation.zip; chmod 644 /system/media/bootanimation.zip; chcon u:object_r:system_file:s0 /system/media/bootanimation.zip; sync'
# 恢复 Logo，仅使用本屏自己的备份
adb -s $d shell 'dd if=/data/local/tmp/rs485-logo.factory.img of=/dev/block/by-name/logo bs=1M && sync'
adb -s $d reboot
```

构建和旧 Termux 路线细节见 [Android 部署说明](ANDROID_DEPLOYMENT.md)。
