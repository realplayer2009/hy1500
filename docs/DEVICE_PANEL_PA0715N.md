# 现场屏硬件笔记：PA0715-N（RK3562 安卓工控一体机）

> 来源：《PA0715-N 产品规格书 V1.02》（深圳冠弈科技）。本文只记录**与 RS485Control 程序相关的部分**，完整规格以原 PDF 为准。
> 现场屏即 AGENTS.md 中的 rk3562_t 面板（`getprop ro.product.model` = rk3562_t）。

## 一、硬件规格摘要

| 项 | 参数 |
|---|---|
| 屏 | 7 寸电容触摸，1024×600（16:9），350 cd/m²，全视角 |
| CPU | Rockchip RK3562，四核 Cortex-A53 @2.0GHz，G52 2EE GPU，1TOPS NPU |
| 内存/存储 | 2G/4G DDR4；16G/32G eMMC |
| 系统 | Android 13.0，开放 root 权限，支持 OTA |
| 网口 | 10/100M 自适应，可设静态 IP；支持 WiFi/4G/以太网三网共存 |
| 串口 | **COM1 = ttyS01，默认 RS485**；COM2 = ttyS02，默认 RS232（两者均可选配反转） |
| USB | USB 3.0（可 OTG/ADB 调试）+ USB 2.0 |
| 音频 | 3.5mm 耳机麦克二合一 + 功放接口；内置喇叭选配 |
| 电源 | DC 12V 圆孔（外径 5.5 / 内径 2.1） |
| 时钟 | **内置实时时钟供电电池**；支持定时开关机、来电自启 |
| 环境 | 工作 -10~60 ℃，储存 -20~70 ℃，10%~80%RH 无冷凝；宣称 7×24 稳定运行 |

## 二、与 RS485Control 相关的要点

### 1. 平台匹配（确认无坑）

- **1024×600** 正是程序 UI 的设计分辨率（主窗口 1024×600、最小 800×480），无需适配。
- RK3562 / 7×24 / -10~60 ℃ 与无人值守场景匹配；温控目标 30 ℃ 一类工况在环境范围内。

### 2. ⚠️ 串口号对账（换板/重烧系统后必须核对）

规格书端子与程序配置的对应关系：

| 规格书端子 | 系统端口 | 程序配置（app.ini） |
|---|---|---|
| COM1（默认 RS485） | ttyS01 | Port0 = **/dev/ttyS4** ← 不一致，现场能通说明该台 COM1 实际接 UART4 |
| COM2（默认 RS232） | ttyS02 | Port1 = /dev/ttyS2（ttyS2 即 ttyS02）✓ |

现状：现场通信正常，说明**这台屏的 RS485 总线实际挂在 ttyS4**。但更换屏、重烧系统或按规格书接线时，端口可能变回 ttyS01——届时轮询全超时。排查方法：`ls /dev/ttyS*`，再用 `rs485_modbus_debug.py --port /dev/ttySx scan` 找到有从站响应的口，同步改 app.ini。

### 3. 断电时间不准 → 先查 RTC 电池

规格书明确“内置实时时钟供电电池”，**正常掉电后系统时间应保持**。程序里的“⚠ 系统时间异常”检测是兜底：

- 若掉电重启后**没有**该提示 → RTC 正常，此前的时间漂移是偶发，继续观察；
- 若**每次掉电都提示** → RTC 电池耗尽，需更换（硬件维修），不是程序问题。

### 4. 亮度控制在本题材上的四条路（现状 + 建议）

原生 APK（`com.rs485.control`）现直接设置当前 Activity 的窗口 `screenBrightness`，在 Android UI 线程异步执行，不需要系统设置写权限。高级设置可点击滑轨定位、拖动大滑块或用每次 5% 的 −/+ 调整；亮度预览仍需保存，离开时选择“不保存”会恢复。本应用退出前台后窗口亮度覆盖失效，不改变其他应用的亮度。下表保留 Linux/Termux 后端的现场情况。

| 路径 | 现状 |
|---|---|
| sysfs `/sys/class/backlight/*/brightness` | app 以 u0_a90 运行，无写权限 → 失败 |
| `settings put system screen_brightness` | 实测抛 SecurityException → 失败 |
| `termux-brightness` | 未安装 termux-api → 不可用 |
| **`su 0 sh -c 'echo N > ...'`** | 规格书明确开放 root，**本机最可行，待实现** |

注：面板自带“自动息屏”（全黑）与程序的“空闲降亮”（降亮度/关背光、触摸即恢复）不是一回事；原生 APK 的自动降亮由窗口亮度接口实现，触摸后恢复；Termux 场景还需核对 X11 前台与对应亮度后端。Android 窗口的最低亮度可能保留微弱背光，0% 不等同于硬件断开背光电源。

### 5. 开机链路与看门狗（kiosk 保障）

规格书“厂商设置”里两项与部署直接相关：

- **开机自启 APP**：当前链路 = 上电自启 → Termux → termux-x11 → `start_rs485.sh` → RS485Control
- **系统守护应用（看门狗）**：APP 退出自动重启、不显示桌面——建议在现场把守护应用配成 Termux:X11，与 `start_rs485.sh` 组成双保险

2026-10-05 接入的新屏未预装 Termux，采用独立原生 `com.rs485.control`：
控制 Activity 设为默认 HOME，同时将厂商开机启动和守护包名指向该应用。
新屏安装与维护按 [`ANDROID_DEPLOYMENT.md`](ANDROID_DEPLOYMENT.md) 的原生 HOME、
宣传开机动画和静态 Logo 章节执行；两阶段静态图也已更换为裕泰通新能源。
上面的 Termux 链路只适用于此前已配置的设备。

### 6. 部署与远程维护通道

- 无线调试：厂商设置 → 网络 ADB 调试（**不走开发者模式**；规格书明确警告勿开开发者模式，有崩溃风险）
- 以太网可设静态 IP，与 WiFi/4G 三网共存；`start_rs485.sh` 已启动 sshd，远程维护走网口最稳
- USB OTG（靠网口的 USB 3.0 口）+ 双公头 USB 线可烧写

### 7. 音频与确认音的关系

面板有功放/可选喇叭，但**操作确认音走子板 OUT5 蜂鸣器**（见 AGENTS.md），与面板音频系统无关——面板静音模式下确认音仍正常。若将来想改用面板喇叭，路线是 termux-api 的 `termux-media-player`。

### 8. 存储与性能余量

- 100 ms 轮询 + 1 s 记录 ≈ 7.8 MB/天，12 GB 上限约 4 年历史。**16G eMMC 版本**要留意系统本身占用后给 data 分区的余量，32G 宽裕。
- 单板场景 2G 内存足够；历史页查询已做后台线程 + 曲线压缩（见 AGENTS.md），4G 版本无压力。

## 三、现场注意事项（规格书原文摘要）

- **勿开“开发者模式”**（规格书警告可能系统崩溃）；网络 ADB 在“厂商设置”里，够用
- **恢复出厂设置会清空已部署程序、配置和历史数据**；原生 APK 按批量安装指南重新安装，旧 Termux 设备需重新配置完整运行环境，不能只运行增量 `android/deploy_device.sh`
- 质保：**一年**免费维修/更换；烧写线须双公头 USB
- 串口绿色端子接线：剥线 3mm，按橙色按钮插底后松手；芯片向下、缺口在左
