# 面板应用升级指南（签名变更后）

> 适用场景：面板上已装的应用与待装 APK **签名不一致**（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`），
> 且该应用是 **Kiosk 设备所有者**导致普通卸载被拒（`DELETE_FAILED_INTERNAL_ERROR`）。
> 常规同签名升级请直接 `adb install --no-streaming -r`，不需要本文步骤。

## 背景

2026-10-17 起签名密钥固定为仓库内的 `android/rs485.keystore`（别名 `androiddebugkey`，
口令 `android`，证书 SHA-256 `E7:5F:13:A9:25:A2:97:33:2D:EA:10:64:86:E1:1E:AA:…`）。
在此之前每轮构建都会现场生成新的 debug 密钥，签名各不相同；面板上现存的应用用的是
一个**已丢失**的密钥签的名，因此无法覆盖安装，必须卸载重装一次。此后同签名即可正常升级。

卸载前设备所有者的处理是唯一需要重启面板的步骤，请安排在停机窗口执行。

## 0. 前置检查

```bash
adb connect 192.168.0.32:5555
adb -s 192.168.0.32:5555 shell pm path com.rs485.control   # 记录当前 APK 路径
adb -s 192.168.0.32:5555 shell dpm list-owners
```

`dpm list-owners` 应显示 `admin=com.rs485.control/.KioskAdminReceiver,DeviceOwner,Affiliated`。
若不是设备所有者，跳到第 3 步。

## 1. 备份应用私有数据（必做）

```bash
BK=/tmp/panel_backup_$(date +%Y%m%d_%H%M%S); mkdir -p "$BK"
adb -s 192.168.0.32:5555 shell "su 0 tar -cf /sdcard/rs485_backup.tar -C /data/data/com.rs485.control files shared_prefs"
adb -s 192.168.0.32:5555 pull /sdcard/rs485_backup.tar "$BK/"
tar -tvf "$BK/rs485_backup.tar"     # 应含 files/config/app.ini、files/data/logs/*.csv、
                                    # .device_index、.last_record_time、shared_prefs
```

备份内容约 2 MB，含现场配置与全部历史 CSV；**卸载后不恢复就会永久丢失**。

## 2. 移除设备所有者（需要 root + 重启）

`dpm remove-active-admin` 对设备所有者会报
`SecurityException: Attempt to remove non-test admin`（该命令只接受声明了
`android:testOnly` 的应用），`pm uninstall` 的各个变体也都会返回
`DELETE_FAILED_INTERNAL_ERROR`，因此只能直接改设备策略存储：

设备所有者记录在**两个**文件里，都要清掉（2026-10-17 实测：只删 `device_policies.xml`
重启后 `dpm list-owners` 仍显示设备所有者，因为真正的持有记录在 `device_owner_2.xml`）：

- `/data/system/device_owner_2.xml` —— 设备所有者本身（`device-owner/name`）
- `/data/system/device_policies.xml` —— 活动管理员、`lock-task-component` 白名单等

```bash
# 2.1 备份两个文件
adb -s 192.168.0.32:5555 shell "su 0 cp /data/system/device_owner_2.xml /sdcard/device_owner_2.xml.bak"
adb -s 192.168.0.32:5555 shell "su 0 cp /data/system/device_policies.xml /sdcard/device_policies.xml.bak"
adb -s 192.168.0.32:5555 pull /sdcard/device_owner_2.xml.bak /tmp/
adb -s 192.168.0.32:5555 pull /sdcard/device_policies.xml.bak /tmp/

# 2.2 删除两个文件
adb -s 192.168.0.32:5555 shell "su 0 rm -f /data/system/device_owner_2.xml /data/system/device_policies.xml"
```

# 2.3 重启面板（约 1-2 分钟，期间应用停止记录）
adb -s 192.168.0.32:5555 reboot
adb connect 192.168.0.32:5555
adb -s 192.168.0.32:5555 wait-for-device
sleep 60

# 2.4 确认设备所有者已解除
adb -s 192.168.0.32:5555 shell dpm list-owners     # 应显示 "No device owners" 之类
```

> `device_policies.xml` 是二进制格式，不要尝试手工编辑；直接删除后系统会按"无策略"初始化。
> 若需回退，把 2.1 的备份推回 `/data/system/device_policies.xml` 后再重启即可。

## 3. 卸载旧应用

```bash
adb -s 192.168.0.32:5555 shell am force-stop com.rs485.control
adb -s 192.168.0.32:5555 uninstall com.rs485.control
```

## 4. 安装新 APK

```bash
adb -s 192.168.0.32:5555 install --no-streaming -r \
    android/dist/RS485Control-arm64-v8a-debug.apk
```

**必须加 `--no-streaming`**：该型号面板流式安装会把 `libc++_shared.so` 落成全零导致闪退。

安装前可自检签名是否为仓库密钥：

```bash
keytool -printcert -jarfile android/dist/RS485Control-arm64-v8a-debug.apk | grep SHA256
# 应为 E7:5F:13:A9:25:A2:97:33:2D:EA:10:64:86:E1:1E:AA:15:4A:88:D7:31:C8:A1:98:59:E4:24:D6:6F:83:11:4C
```

## 5. 恢复数据

```bash
adb -s 192.168.0.32:5555 shell "su 0 mkdir -p /data/data/com.rs485.control/files /data/data/com.rs485.control/shared_prefs"
adb -s 192.168.0.32:5555 push /tmp/rs485_backup.tar /sdcard/rs485_backup.tar
adb -s 192.168.0.32:5555 shell "su 0 tar -xf /sdcard/rs485_backup.tar -C /data/data/com.rs485.control"

# 属主必须取本次安装的 uid, 不能沿用备份里的 u0_a90:
# 卸载重装后 Android 会分配新 uid(如 u0_a91), 用旧 uid chown 会让应用读不到自己的
# 私有目录, 启动即退并报 "Cannot initialize Android app file: config/app.ini"
APPU=$(adb -s 192.168.0.32:5555 shell "su 0 stat -c %U /data/data/com.rs485.control" | tr -d '\r')
APPG=$(adb -s 192.168.0.32:5555 shell "su 0 stat -c %G /data/data/com.rs485.control" | tr -d '\r')
adb -s 192.168.0.32:5555 shell "su 0 chown -R $APPU:$APPG /data/data/com.rs485.control/files /data/data/com.rs485.control/shared_prefs"
adb -s 192.168.0.32:5555 shell "su 0 rm -f /sdcard/rs485_backup.tar"
```

**只有这一步需要重装路径。** 若签名一致（2026-10-17 起仓库固定了签名密钥，CI 每轮
产物指纹都是 `E7:5F:13:A9…`），覆盖安装 `adb install --no-streaming -r` 即可，应用
无需卸载、uid 不变、设备所有者与 HOME 全部保留，也不必执行本文第 2、3、6 步。

若安装后应用已经启动过一次，`files/` 下可能已生成新的 `config/app.ini`（来自 APK assets 的
首次复制）和空的 `data/logs/`；此时应先删掉这两个新目录再解包，避免旧配置被覆盖。

## 6. 重设 Kiosk（恢复原锁定行为）

```bash
adb -s 192.168.0.32:5555 shell dpm set-active-admin --user 0 com.rs485.control/.KioskAdminReceiver
adb -s 192.168.0.32:5555 shell dpm set-device-owner --user 0 com.rs485.control/.KioskAdminReceiver
adb -s 192.168.0.32:5555 shell dpm set-active-admin --user 0 com.rs485.control/.KioskAdminReceiver
adb -s 192.168.0.32:5555 shell cmd package set-home-activity --user 0 com.rs485.control/.MainActivity
adb -s 192.168.0.32:5555 shell settings put system xzjh_auto_boot_package_name com.rs485.control
adb -s 192.168.0.32:5555 shell settings put system xzjh_daemon_package_name com.rs485.control
```

`set-device-owner` 要求设备上没有已配置的账户；本机当前只有机主用户，可直接设置。
第二次 `set-active-admin` 是必须的：仅设设备所有者时 `KioskAdminReceiver` 不一定进入
活动管理员列表，Activity 恢复前台调用 `setLockTaskPackages` 会因 UID 不匹配抛
`SecurityException` 闪退。

## 7. 启动并验证

```bash
adb -s 192.168.0.32:5555 shell am start -W -n com.rs485.control/.MainActivity
sleep 5
adb -s 192.168.0.32:5555 shell "ps -A -o PID,NAME | grep com.rs485.control"
adb -s 192.168.0.32:5555 shell "su 0 ls -l /data/app/*/com.rs485.control*/lib/arm64/ | head -4"
adb -s 192.168.0.32:5555 shell "su 0 dd if=/data/app/*/com.rs485.control*/lib/arm64/libRS485Control_arm64-v8a.so bs=1 count=4 2>/dev/null | od -An -tx1"
```

native 库头 4 字节应为 `7f 45 4c 46`；若是 `00 00 00 00` 说明又是流式安装损坏，卸载后用
`--no-streaming` 重装。

面板上还需人工确认两项配置，否则本轮新功能不生效：

1. 高级设置（密码 123456）→ 外扩输入接入配置 → IN1 改为"手动自动"
2. 高级设置 → 加热器输出配置 → 缺失的那一路设为"未配置加热器"
