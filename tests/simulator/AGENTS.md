# 模拟器工程取舍

> 后续修改本组件的 agents 请继续维护本文档；仅在固定参数权衡或修正原逻辑语义时记录，采用“问题 + 解决方案选择 + 解释”，没有实际取舍则不强行添加。

- 问题：原温升只计算 OT3/OT4，三个加热器独立控制及输出对切换后，部分加热无温升、备用或状态灯输出却可能造成温升。解决方案选择：跟随模拟运行配置中三组加热器输出对，每组低/高回路分别沿用 0.03/0.06 ℃/s，叠加到同一个热环境；用一阶散热方程的解析解推进内部温度。解释：保留原低/高功率比例，同时覆盖全部加热回路，未分配输出不影响温度；解析解避免不同 tick 间隔改变热响应。这是联调用简化模型，不代表现场热功率标定。

- 问题：外扩实体按键按上升沿切档，持续闭合无法模拟连续按压，短脉冲又可能被轮询漏采。解决方案选择：`press` 和 `z/x/c` 默认闭合 600 ms，使用单调时钟在总线线程中释放；已闭合时拒绝再次按压，`F1~F5` 或 `set` 可保持/释放输入，`press` 支持 100～60000 ms。解释：默认脉冲为常见单板轮询留出采样窗口，不为制造上升沿绕过上位机逻辑；多板、长轮询及重连首帧需要延长或保持输入，先读到断开基线再按下。灯和蜂鸣器只展示上位机实际写入，不在模拟器中伪造联动。

- 问题：原模拟器将 0x000C 与 0x000E 都返回同一外扩输入，掩盖上位机旧地址回退覆盖实际地址的问题，且遗漏主轮询的软件版本寄存器。解决方案选择：补齐 0x0000，0x000C 返回输入位掩码，0x000E 保持可读但返回零，OT/OUT 继续通过 0x0031/0x0033 回读和写入。解释：默认复现项目已记录的现场 firmware 语义，主程序必须正确读取实际输入地址。

- 问题：启动覆盖模拟配置会丢失界面保存的接线和温控参数，固定接线的模拟模型也无法验证动态映射。解决方案选择：项目 `config/app.ini` 补齐缺失字段，已有模拟配置覆盖其值，启动仅强制刷新串口协议、启用状态和隔离的数据目录；`--reset-config` 显式恢复项目配置。总线物理 tick 检查配置文件变化，成功解析后统一更新接线，重复输出对按主程序规则分配。解释：保留联调场景且跟随界面操作；暂时不可读的保存过程保留上一份完整接线，避免部分配置生效。
